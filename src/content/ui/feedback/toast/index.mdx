A toast is a short notification message that confirms what the user just did, such
as saving a form or adding an item to the cart. It is a `<div class="toast">`, with
`data-type` variants for info, warning, and error. The component styles the message; showing and dismissing it is your app's
job.

## Usage

- Use a `<div class="toast">` for a neutral message.
- Add `data-type="info"`, `"warning"`, or `"error"` for an accented variant, and
  pair it with a matching icon marked `aria-hidden="true"`.
- For a success toast, set `--toast-style` to a green. The example builds it from the
  green hue token with `--toast-style: oklch(58% 0.21 var(--hue-green))`.
- Position and animate toasts with utilities and your own show/dismiss logic; the
  component does not place or time them.

## Accessibility

- Render toasts inside a live region so screen readers announce them: `role="status"`
  for routine messages. For errors, use an [Alert](/ui/feedback/alert/) with
  `role="alert"` instead.
- Do not convey meaning by color alone; keep the message text clear, and back the
  `data-type` accent with an icon or wording.

## Variants

### Sticky message

A toast can stay in view while the user keeps scrolling, such as a cart confirmation
at the bottom of a product list. Add the `sticky` utility, place it at the end of the
scrolling content, and pin it to the bottom with `--inset-y: auto 0`. The `role="status"`
announces it when it appears.
