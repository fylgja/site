A search box pairs a query field with its submit button so they read as one
control. It is built on the native [`<search>`](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/search)
element and `<input type="search">`, so the search landmark and the field's clear
button come for free.

## Usage

- Wrap the form in `<search>`. That is what marks the region as search, so no
  `role="search"` is needed.
- Put the `<input>` and `<button>` in a `.input-group`, with `--merge` to drop
  the seam between them so they read as one control.
- Give the input a `<label for>`. Add `sr-only` to the label when the design has
  no room for it.
- Use `type="search"` so browsers offer the clear button and the right keyboard.
- If you use an icon only button, it still needs a name. A `<title>` inside the `role="img"`
  SVG supplies it, so the button announces as "Search" or use `aria-label` to provide a custom name.

## Anatomy

- `<search>` marks the landmark.
- `<form action>` decides where the query goes, so it keeps working without
  JavaScript.
- `.input-group.--merge` joins the field and the button, squaring off the inner
  corners and removing the border between them.
- `<button>` submits. It needs no `type`, since submit is the default in a form,
  and it carries only the icon.

## Accessibility

- The `<search>` element carries the search landmark natively.
- The `<label for>` names the field. A placeholder is not a label.
- The icon button is named by the `<title>` in its SVG. Drop that and the button
  announces as an unlabelled button.
- Both the field and the button are reachable and operable by keyboard with no
  extra work.

## Variants

Drop the button when the field filters live as the reader types, and keep the
`<search>` wrapper. For the joined look with a select or a second button, see the
[Input Group](/library/components/input-group/) docs.
