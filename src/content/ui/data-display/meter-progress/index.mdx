`<meter>` and `<progress>` are the two native bars, and browsers style them
inconsistently out of the box. Fylgja Form Extend gives both a consistent track
and fill, while leaving the semantics and the color states to the browser.

## Usage

- Use `<meter>` for a value inside a known range, and `<progress>` for how far a
  task has run.
- Give a meter `min`, `max` and `value`. Add `low`, `high` and `optimum` to let
  the browser color it good, average or poor on its own.
- Give a progress bar `max` and `value`, or leave `value` off entirely for an
  indeterminate bar.
- Put the text inside the element as a fallback, for example `82%`. Browsers that
  render the bar ignore it.

## Anatomy

- `<label>` wraps the bar and its text, so no `for` is needed.
- `min` / `max` set the range, `value` the current point.
- `low` / `high` / `optimum` describe what a good value is, which is what drives
  the color, not a class.

## Accessibility

- Both elements carry their role and value natively, so a screen reader announces
  the number without any ARIA.
- Color alone must not carry the meaning. Keep the label, and state the value in
  text when it matters.
- An indeterminate progress bar animates. Readers who prefer reduced motion get a
  calmer version from Fylgja.
