A gauge shows a single value against its range as a dial, the way a dashboard
shows CPU load or battery level. It is the native `<meter>` from the
[Meter](/ui/data-display/meter/) component with a different look. The dial reads
`value`, `min`, `max`, `low`, `high` and `optimum` from the element with typed
`attr()`, so the markup is all the data the chart needs, with no custom properties
to keep in sync.

## Usage

1. Write a regular `<meter>` with `min`, `max` and `value`. Add `low`, `high` and
   `optimum` to color it by state.
2. Wrap it in a `<label class="gauge inline-grid align-center gap-sm">` with the
   name as text, so the meter is labelled without a `for`.
3. Add a `<span class="lead" aria-hidden="true">` after the meter with the value as you want it
   shown. CSS cannot format a number, so this is the text in the middle of the dial.
4. Add the CSS from under the preview. Size the dial with `--gauge-size`, and the ring
   with `--gauge-thickness` as a share of the radius, such as `0.22`.

## Anatomy

| Part                        | Responsibility                                                    |
| --------------------------- | ----------------------------------------------------------------- |
| `<label class="gauge">`     | Names the meter and stacks the dial, value and name.              |
| `<meter>`                   | Holds the data, and is painted as the dial.                       |
| `<span aria-hidden="true">` | The formatted value in the middle of the dial.                    |
| `attr()` reads              | Pull the numbers from the meter's attributes into the CSS.        |
| `conic-gradient()`          | Draws the 270 degree arc, filled up to the value.                 |
| `radial-gradient()` dots    | Round off both ends of the track and the end of the fill, like the meter's radius. |
| `--success` / `--warning` / `--error` | Color the arc by state, matching the [Meter](/ui/data-display/meter/). |

## Accessibility

- The meter keeps its role and value, so a screen reader announces the name from
  the label and the value from the element. The dial is only a background.
- The value span is hidden from assistive technology, because the meter already
  reports its value.
- State is shown by color, so keep the value in text and pick thresholds that a
  reader can make sense of from the number alone.

## Browser support

The dial needs typed `attr()`, plus `sign()` and `abs()` to work out the state.
Typed `attr()` is the newest of these and is available in Chromium based browsers
first. The styles sit in an `@supports` block, so other browsers fall back to the
plain [Meter](/ui/data-display/meter/) bar with the value under it.

### With the attr() polyfill

The [Fylgja CSS attr() Polyfill](/library/extensions/css-attr-polyfill/) brings the
dial to every browser. It runs at build time, scans your markup for the attribute
values you use, and writes a static rule for each one, such as `value="59"`.
Browsers with typed `attr()` keep using the original rules.

1. Remove the `@supports` wrapper and keep its contents. The polyfill adds its own
   guarded fallback, and inside the wrapper that fallback would never apply.
2. Keep the `attr()` reads in the flat `.gauge meter` rule. The polyfill does not
   read declarations inside nested rules.
3. Point `content` at your templates. Values that only exist at runtime, like a
   live CPU reading set from JavaScript, cannot be scanned, so safelist their
   range, such as `"value": "0..100"`. Every value becomes a rule, so keep the
   range to whole numbers where you can.
