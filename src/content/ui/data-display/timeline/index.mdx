A timeline lists events in order along a vertical line, each with a date, a title,
and a short description. It is a plain `<ol>`, so the order is real for assistive
tech, and every date is a `<time>` element with a machine readable `datetime`.

## Usage

- Put the events in an `<ol role="list" class="timeline">`, one `<li>` per event,
  newest or oldest first as the content needs.
- Pair the date and title in an `<hgroup>`, with the date in a `<p>` and a
  `<time datetime>` inside it. The `<hgroup>` keeps them tight together, while the
  description below gets the usual paragraph spacing.
- The small `.timeline` rule draws the line as a border on the list and each
  marker as a `::before` on the item. Tune it with `--timeline-gap`,
  `--timeline-line`, `--timeline-marker`, and `--timeline-marker-size`.

## Anatomy

| Part                           | Responsibility                                       |
| ------------------------------ | ---------------------------------------------------- |
| `<ol class="timeline">`        | The list of events, and the vertical line.           |
| `<li>`                         | One event, with its marker drawn in `::before`.      |
| `<hgroup>`                     | Keeps the date and the event title together.         |
| `<time datetime>`              | The date, readable by people and machines.           |

## Accessibility

- `role="list"` keeps the list semantics that Safari drops once `list-style` is
  removed.
- The line and markers are decoration drawn in CSS, so assistive tech skips them.
  If a marker carries meaning, such as a finished or upcoming step, say so in the
  text too.
- Use a heading level that fits the page outline around the timeline.
